# Level Up Skill Requirements — Software Engineers (.NET)

> **Source:** Level Up / EPAM Assessment Portal export — Primary Skill: .NET
> **Covers titles:** A2 Software Engineer · A3 Senior Software Engineer · A4 Lead Software Engineer
> **Used by:** `@self-presentation-reviewer` and `@pre-assessment-question-generator`

---

## General Title Expectations

### Client Relations

| Title | Expectation |
|---|---|
| **A2** | Actively participates in project meetings. Able to directly communicate with a customer. Recommended: direct communication for requirements gathering, demos, and showing results of own work. |
| **A3** | Actively participates in project meetings. Can lead/moderate conversations. Directly communicates with a customer for requirements gathering, demos, and presenting own or team results. Recommended: success story of convincing a customer to adopt a proposed technical solution. |
| **A4** | Plays a customer-facing role. Proposes suitable technical solutions that address customer needs with clear justification and alternative approaches. Able to present technical solutions to the customer. Recommended: experience working on-site with the customer. |

### Team Management

| Title | Expectation |
|---|---|
| **A2** | Works without direct supervision. |
| **A3** | Plays a mentor role for less experienced colleagues. Can organize teamwork and get things done. |
| **A4** | Uses team leadership techniques (motivation, delegation, conflict resolution, ownership). Knows team members' strengths and weaknesses, communicates shared vision. Promotes engineering culture and helps less mature engineers advance. |

### Architecture on Practice (General)

| Title | Expectation |
|---|---|
| **A2** | Participates in creating module design and/or its components. Able to explain and use design patterns. Able to read and create software engineering diagrams. Experience writing technical documentation. Recommended: explains non-functional requirements on current/previous projects. |
| **A3** | Experience creating system/module design and components. Explains pros/cons of proposed solutions. Makes decisions in area of responsibility, provides multiple solutions with justification. Explains non-functional requirements (performance, security). Recommended: experience proposing technical solutions or enhancements. |
| **A4** | Designs system components or whole solutions. Knows architecture styles (SOA, event-driven, microservices). Fully describes and compares design patterns. Explains non-functional requirements. Explains which decisions were made, alternatives considered, and criteria used. Writes technical documentation per best practices. |

### Development Experience (General)

| Title | Expectation |
|---|---|
| **A2** | Provides working solution for an engineering problem and takes ownership of implementation. Knows development tools/best practices and applies them effectively. Recommended: experience proposing technical solutions or enhancements. |
| **A3** | Self-management. Works without supervision, supports/supervises less experienced colleagues. Advanced level theoretical knowledge and production experience in at least one technical area. Experience proposing technical solutions. Recommended: troubleshooting success stories, technical interview participation, mentoring experience, tech talks/conference speaking. |
| **A4** | Decision-maker. Practical experience providing Technical Leadership. Solves technical and non-technical impediments. Successful troubleshooter. Knows how to start a new project from scratch technically. Proven record of conducting technical interviews. Plans and prioritizes teamwork effectively. Recommended: knowledge sharing, mentoring, active conference participation. |

### Engineering Excellence (General)

| Title | Expectation |
|---|---|
| **A2** | Follows established development processes (SCRUM, Kanban, Waterfall). Knows and follows engineering practices on the project. Explains code quality. Follows software engineering principles. Basic knowledge of Software Quality Control. Can participate in Code Review as reviewer. Recommended: understands and adopts EPAM EngX practices. |
| **A3** | Follows established processes, can describe pros/cons for the project. Knows and follows best engineering practices, explains pros/cons and which are used on current project. Explains code quality and how to measure it, knows code metrics. Experience creating efficient unit/component/integration tests. Follows SOLID, DRY, KISS with justification. Works according to EPAM EngX practices. Recommended: actively improves project processes, experience with end-to-end automated acceptance tests. |
| **A4** | Knows theory of SDLC, SCRUM, Kanban, Waterfall; can implement them in a team, compare them, and evaluate which is better for a given project. Experience setting up or enhancing development process per best practices with at least one example. Explains how to guarantee quality and handle technical debt. Knows EPAM EngX practices with pros/cons per project. Knows code quality metrics and uses automated tools. Clear understanding of different types of software testing. |

## Quick Reference: What Changes Across Titles

| Area | A2 → A3 Shift | A3 → A4 Shift |
|---|---|---|
| Technical depth | Intermediate → Advanced in most core skills | Advanced → Expert in core skills (.NET, C#, Testing) |
| Ownership | Works independently | Makes decisions, provides technical leadership to the team |
| Architecture | Participates in module design | Designs whole systems, compares architectural styles |
| Leadership | No leadership requirements | Mentoring, team organization, conflict resolution |
| Customer | Direct communication | Customer-facing role, proposing solutions |
| Hiring | Not required | Required (Intermediate/Advanced) |
| Security | Optional | Required |
| ORM | ADO.NET / EF (A2-specific) | .NET ORM (A3+) |
| MQ | Novice | Intermediate |
